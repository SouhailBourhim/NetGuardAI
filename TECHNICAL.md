## 1. System overview

NetGuardAI runs two detection pipelines independently and in parallel at inference time:

```
Raw network flow
       │
       ▼
  Feature scaling (StandardScaler)
       │
       ├──────────────────────────────────────────┐
       │                                          │
       ▼                                          ▼
Supervised pipeline                    Autoencoder pipeline
(XGBoost / RF / LR)                   (LSTM Autoencoder)
       │                                          │
       ▼                                          ▼
 Predicted class                     Reconstruction error
 (BENIGN or attack type)             vs. anomaly threshold
       │                                          │
       └──────────────┬───────────────────────────┘
                      ▼
              Unified prediction
         { label, confidence, anomaly_score }
```

The supervised pipeline handles **known attack classification**. The autoencoder provides a complementary **zero-day anomaly signal** for traffic patterns not seen during supervised training.

## 2. Dataset

**Source:** [CICIDS2017](https://www.unb.ca/cic/datasets/ids-2017.html) — Canadian Institute for Cybersecurity  
**Files used:** `data/raw/MachineLearningCVE/` (8 CSVs, one per day/session)

### Class inventory

| Class | Count | Split |
|---|---|---|
| BENIGN | 2,095,057 | train + test |
| DDoS | 128,014 | train + test |
| DoS Hulk | 172,846 | train + test |
| PortScan | 90,694 | train + test |
| DoS GoldenEye | 10,286 | **test only** |
| DoS Slowhttptest | 5,228 | train + test |
| DoS slowloris | 5,385 | train + test |
| SSH-Patator | 3,219 | train + test |
| FTP-Patator | 5,931 | train + test |
| Bot | 1,948 | train + test |
| Web Attack – Brute Force | 1,470 | train + test |
| Web Attack – XSS | 652 | train + test |
| Web Attack – Sql Injection | 21 | train + test |
| Infiltration | 36 | train + test |
| Heartbleed | 11 | **test only** |

`DoS GoldenEye` and `Heartbleed` are absent from the training split because they appear exclusively in Wednesday's traffic, which falls within the temporal test window (last 20%).

### Raw feature set

79 columns total: 78 flow-level features (packet lengths, inter-arrival times, flag counts, bulk rates, etc.) + 1 `Label` column. Features were generated by CICFlowMeter from raw PCAP files.

## 3. Phase 1 — Preprocessing pipeline

**Entry point:** `src/preprocess.py`

### Steps

#### 3.1 Load & concatenate
All 8 CSVs are read with `pandas.read_csv(low_memory=False)` and concatenated in alphabetical filename order. This preserves the natural temporal ordering (Friday → Monday → Thursday → Tuesday → Wednesday).

#### 3.2 Column name normalisation
Leading/trailing whitespace stripped from all column names (the raw CSVs have a leading space on `' Label'`).

#### 3.3 Deduplication
`DataFrame.drop_duplicates()` — removed 308,381 rows (10.9% of raw data).

#### 3.4 Inf / NaN removal
`±inf` replaced with `NaN`, then all rows containing any `NaN` dropped. Removed 1,564 rows.

#### 3.5 Constant feature removal
Features with zero variance across the dataset are dropped. Removed 8 features:

```
Bwd PSH Flags, Bwd URG Flags,
Fwd Avg Bytes/Bulk, Fwd Avg Packets/Bulk, Fwd Avg Bulk Rate,
Bwd Avg Bytes/Bulk, Bwd Avg Packets/Bulk, Bwd Avg Bulk Rate
```

#### 3.6 Correlation filter
Pearson correlation matrix computed on remaining features. For any pair with |r| > 0.95, the second feature (upper triangle) is dropped. Removed 23 features, retaining **47 features**.

Notable drops: `Total Backward Packets`, `Fwd IAT Total`, `Subflow Fwd/Bwd Packets/Bytes`, `Idle Mean/Max/Min` (collinear with other IAT/active features).

#### 3.7 Label encoding

Two encodings are produced and saved separately:

| Encoding | Scheme | File |
|---|---|---|
| Binary | BENIGN → 0, everything else → 1 | `y_train_binary.npy`, `y_test_binary.npy` |
| Multi-class | `sklearn.LabelEncoder` (alphabetical) | `y_train_multi.npy`, `y_test_multi.npy` |

#### 3.8 Temporal train/test split

**No shuffling is applied at any stage.** The dataset is split at the 80th percentile of row index:

| Set | Rows |
|---|---|
| Train | 2,016,638 |
| Test | 504,160 |

Preserving temporal order prevents data leakage — a random split would allow future traffic patterns to inform past predictions.

#### 3.9 Scaling

`StandardScaler` is fit **on the training set only** and used to transform both train and test. The fitted scaler is persisted to `data/processed/scaler.pkl` for use at inference time.

#### 3.10 SMOTE

`imbalanced-learn.SMOTE` is applied to the training set **only** (never to the test set) to address class imbalance.

| Dataset | Before SMOTE | After SMOTE |
|---|---|---|
| Binary train | 2,016,638 (87% benign) | 3,516,176 (50/50) |
| Multi-class train | 2,016,638 (13 classes) | 22,855,144 (balanced) |

The unaugmented scaled training set (`X_train_scaled.npy`) is also saved separately for the autoencoder, which must train on real benign samples only.

### Output files

| File | Shape | Description |
|---|---|---|
| `X_train.npy` | (3,516,176 × 47) | Binary-SMOTE features |
| `X_test.npy` | (504,160 × 47) | Scaled test features |
| `y_train_binary.npy` | (3,516,176,) | SMOTE binary labels |
| `y_test_binary.npy` | (504,160,) | Binary test labels |
| `X_train_multi.npy` | (22,855,144 × 47) | Multi-class SMOTE features |
| `y_train_multi.npy` | (22,855,144,) | SMOTE multi-class labels |
| `y_test_multi.npy` | (504,160,) | Multi-class test labels |
| `X_train_scaled.npy` | (2,016,638 × 47) | Unaugmented scaled train (autoencoder) |
| `y_train_binary_raw.npy` | (2,016,638,) | Unaugmented binary labels |
| `scaler.pkl` | — | Fitted `StandardScaler` |
| `label_encoder.pkl` | — | Fitted `LabelEncoder` (15 classes) |
| `feature_cols.pkl` | — | List of 47 retained feature names |

## 4. Phase 2 — Supervised learning

**Entry point:** `src/train_supervised.py`

### Models

All three models are trained for both binary and multi-class classification, resulting in 6 MLflow runs.

| Model | Key hyperparameters |
|---|---|
| `LogisticRegression` | `C=1.0`, `solver='saga'`, `max_iter=1000` |
| `RandomForestClassifier` | `n_estimators=200`, `max_depth=20`, `min_samples_leaf=2` |
| `XGBClassifier` | `n_estimators=300`, `max_depth=8`, `lr=0.1`, `subsample=0.8`, `colsample_bytree=0.8` |

### Multi-class label remapping

Because `DoS GoldenEye` (index 3) and `Heartbleed` (index 8) are absent from the training split, the 15-class label space is remapped to contiguous indices 0–12 before fitting. Test samples belonging to the two missing classes are excluded from evaluation. This is handled in `run()` before any model is trained and does not affect the binary pipeline.

### Training data cap

The multi-class SMOTE output (22.8M rows) is subsampled to `MAX_MULTICLASS_TRAIN = 500,000` using stratified sampling (`sklearn.utils.resample`) to keep training times tractable on a local machine. The binary pipeline uses the full 3.5M SMOTE output.

### Metrics logged per run

`accuracy`, `f1_weighted`, `precision_weighted`, `recall_weighted`, `f1_macro`, `roc_auc` (binary only).

### Artifacts logged per run

- `classification_report.txt` — full per-class breakdown
- `confusion_matrix.png` — annotated heatmap
- `model/` — serialised sklearn model (MLflow artifact)

### Results

**Binary classification**

| Model | Accuracy | F1 (weighted) | ROC-AUC |
|---|---|---|---|
| XGBoost | 0.9915 | 0.9915 | 0.9999 |
| Random Forest | 0.9807 | 0.9806 | 0.9981 |
| Logistic Regression | 0.8733 | 0.8762 | 0.9666 |

**Multi-class classification** (13 classes, 500K training samples)

| Model | Accuracy | F1 (weighted) | F1 (macro) |
|---|---|---|---|
| XGBoost | 0.9947 | 0.9963 | 0.1659 |
| Random Forest | 0.9873 | 0.9919 | 0.1802 |
| Logistic Regression | 0.7567 | 0.8529 | 0.1352 |

The low `f1_macro` scores reflect the heavily imbalanced test set — rare classes like Infiltration (36 samples) and Web Attack – Sql Injection (21 samples) are almost never seen by the model at evaluation, pulling the unweighted macro average down.

### Model promotion

`src/promote_best_model.py` queries the `netguardai_binary` experiment, ranks finished runs by `f1_weighted`, registers the winner under the name `netguardai_best_binary`, and transitions it to the `Production` stage in the MLflow Model Registry, archiving any previously promoted version.

## 5. Phase 2 — LSTM Autoencoder

**Entry point:** `src/train_autoencoder.py`

### Rationale

The supervised pipeline can only classify attacks it was trained on. The autoencoder addresses this by learning a compressed representation of **normal traffic**. Any flow whose reconstruction error significantly exceeds what the model learned to reconstruct is flagged as anomalous — including novel attack types.

### Input preparation

Training data: `X_train_scaled.npy` filtered to benign-only rows (`y_train_binary_raw == 0`), giving 1,758,088 samples.

Flows are grouped into **non-overlapping windows** of `WINDOW_SIZE = 50` consecutive flows:

```
(1,758,088 flows) → (35,161 windows × 50 timesteps × 47 features)
```

A 90/10 split produces ~31,644 training windows and ~3,516 validation windows. The validation set is used both for early stopping (via `ReduceLROnPlateau`) and for computing the anomaly threshold.

### Architecture

```
Input: (batch, 50, 47)
  │
  ▼
Encoder LSTM — hidden=64, layers=2, dropout=0.2
  │  (batch, 64)  ← last hidden state
  │
  ▼  repeat across 50 timesteps
  │
Decoder LSTM — hidden=64, layers=2, dropout=0.2
  │
  ▼
Linear(64 → 47)
  │
Output: (batch, 50, 47)  ← reconstruction
```

Loss: `MSELoss` over all timesteps and features.

### Training

| Hyperparameter | Value |
|---|---|
| Epochs | 15 |
| Batch size | 256 |
| Optimiser | Adam, lr=1e-3 |
| LR scheduler | ReduceLROnPlateau (patience=3, factor=0.5) |
| Gradient clipping | max norm = 1.0 |
| Device | MPS (Apple Silicon) / CPU fallback |

Best checkpoint (lowest validation loss) is restored after training.

### Anomaly threshold

The anomaly threshold is set at the **95th percentile** of per-window MSE reconstruction errors on the benign validation set. This means ~5% of normal traffic is expected to be flagged as anomalous (false positive rate ≈ 0.05 at window level).

Threshold value: `1.4834`

The threshold is saved to `data/processed/autoencoder_threshold.npy` for use at inference time.

### Inference

At inference time, incoming flows are grouped into windows of 50. Each window's MSE reconstruction error is computed and compared to the threshold. The per-flow anomaly score is the reconstruction error of its window.

### Results

Evaluated on the full test set (504,160 flows → 10,083 windows):

| Metric | Score |
|---|---|
| Accuracy | 0.8869 |
| F1 (weighted) | 0.8872 |
| Precision | 0.8214 |
| Recall | 0.8421 |
| ROC-AUC | 0.9247 |

Final training loss: `0.7234` · Final validation loss: `0.7871`

## 6. Phase 3 — Inference & API

### 6.1 `src/predict.py` — unified inference module

`predict.py` exposes three public functions used by the API and notebooks:

| Function | Description |
|---|---|
| `predict(features)` | Single-flow prediction — dict or ordered list of 47 floats |
| `predict_batch(feature_list)` | Batch prediction over a list of flows |
| `model_info()` | Returns model names, feature list, class names, threshold |

All models are cached in the `_Models` singleton and loaded once on first call.

**Dual-pipeline logic per flow:**
1. Scale features using the fitted `StandardScaler`
2. Binary classifier → `is_attack` + `confidence`
3. If attack: multi-class classifier → specific attack `label`
4. Autoencoder → tile flow into window of 50, compute MSE → `anomaly_score`
5. `is_anomaly = anomaly_score > threshold`

**Single-flow autoencoder scoring:** Since the autoencoder was trained on windows of 50 consecutive flows, single-flow inference approximates by tiling the flow 50 times into a synthetic window. This preserves the input shape without requiring buffering at the API layer.

**Model loading — Python 3.14 / XGBoost 3.x compatibility:**

Two issues were encountered and resolved:

1. `mlflow.sklearn.load_model()` causes a segfault on Python 3.14 with XGBoost 3.x. Models are instead loaded directly from their pickle artifacts (`data/processed/model_binary.pkl`, `model_multi.pkl`) bypassing the MLflow loading stack entirely.

2. Importing `torch` before unpickling XGBoost models causes a segfault due to a memory allocator conflict between PyTorch's custom allocator and XGBoost's runtime. Fixed by lazy-importing `torch` inside `_Models.__init__()` after all sklearn/XGBoost artifacts are loaded.

3. The autoencoder `.pth` was serialised by MLflow using cloudpickle (full model object, not state dict only). Loaded with `torch.load(..., weights_only=False)`.

**Model export:** A one-time export copies the best-run artifacts from the MLflow model store (`mlruns/.../models/m-xxx/artifacts/`) to `data/processed/` for direct loading:

| File | Source |
|---|---|
| `model_binary.pkl` | Best binary XGBoost run artifact |
| `model_multi.pkl` | Best multi-class XGBoost run artifact |
| `model_autoencoder.pth` | Best autoencoder run artifact (cloudpickle) |

### 6.2 `api/main.py` — FastAPI service

**Startup:** Models are pre-loaded during the lifespan context (`@asynccontextmanager`) before the server begins accepting requests, so the first request is not penalised by load time.

**Endpoints:**

| Method | Path | Input | Output |
|---|---|---|---|
| `GET` | `/health` | — | `{"status": "ok"}` |
| `GET` | `/model/info` | — | Model metadata + feature/class lists |
| `POST` | `/predict` | `{"features": dict or list}` | Single `PredictionResponse` |
| `POST` | `/predict/batch` | `{"flows": [dict or list, ...]}` | `BatchPredictionResponse` |

**Request format:** Features can be submitted as either a named dict (`{"Destination Port": 80.0, ...}`) or an ordered list of 47 floats matching `feature_cols` order. Both are accepted at every prediction endpoint.

**Response schema:**

```json
{
  "label":             "DoS Hulk",
  "is_attack":         true,
  "confidence":        1.0,
  "anomaly_score":     0.737048,
  "is_anomaly":        false,
  "anomaly_threshold": 1.483423
}
```

Interactive documentation: `http://localhost:8000/docs` (Swagger UI).

## 8. Known limitations

| Issue | Impact | Notes |
|---|---|---|
| Temporal split leaks Wednesday attacks into test only | `DoS GoldenEye`, `Heartbleed` untrained | Inherent to CICIDS2017 day-by-day structure |
| Multi-class SMOTE capped at 500K | Model trained on ~2% of available SMOTE data | Increase `MAX_MULTICLASS_TRAIN` for better recall on rare classes |
| LSTM window boundary effects | Flows at window edges get the same score as interior flows | Overlapping windows would improve per-flow granularity at inference |
| Autoencoder threshold is static | Threshold set once from val set; no drift adaptation | A sliding-window percentile would adapt to traffic shifts over time |
| No timestamp feature | Temporal ordering preserved by row order, not an explicit feature | CICFlowMeter timestamps could be added as a cyclic feature |
